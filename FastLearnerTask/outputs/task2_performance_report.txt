- Spark Memory Use:                42.0 MB (Utilizes In-Memory RDD Buffers)

KEY ARCHITECTURAL DIFFERENCES:
1. In-Memory Computing vs Disk Spills:
   Hadoop MapReduce persists all intermediate key-value pairs to local disks between the
   Map and Reduce phases (Shuffle/Sort), causing intense Disk I/O bottlenecks. In contrast,
   Spark stores intermediate state in RAM across Resilient Distributed Datasets (RDDs).

2. Execution Pipeline (DAG vs 2-Stage MR):
   MapReduce strictly adheres to a linear Map -> Sort/Spill -> Reduce workflow. Spark constructs
   a Directed Acyclic Graph (DAG) optimized by Catalyst and Tungsten, fusing transformations
   together into single execution stages.

3. Process Model Overhead:
   MapReduce spawns separate JVM tasks for individual mappers/reducers with high startup latency,
   whereas Spark reuses persistent multi-threaded executors across tasks.
